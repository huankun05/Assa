## 一、现状盘点（实测）

### 1.1 Assa 现有存储点

| 位置 | 内容 | 类型 | 问题 |
|---|---|---|---|

| `Assa/data/tmp/` | 录音缓冲 `in_*.wav` | **临时** | **只写不删，无任何清理** |

### 1.2 hermes_core 存储点（移植后必须改造）

| 位置 | 内容 | 现状 |
|---|---|---|
| `HERMES_HOME`（默认 `%LOCALAPPDATA%\hermes\`） | SessionDB `state.db` 等 | 环境变量可覆盖 ✓ |
| `server/data/core.db` | 记忆库 `memory_fragments` 表 | **硬编码相对路径** `Path(__file__).parent.parent.parent / "data" / "core.db"`，且与 desk-pet 的 `core.api_server` 共用——移植后必须重新指向 Assa 数据目录 |
| 记忆库同目录 | `memory_injections.jsonl`（注入溯源）、`memory_autogen.json`（自动生成元数据） | 基于 `get_db_path().parent`，跟随 db 路径 ✓ 无需改 |
| soul / emotion / time | 纯内存 dataclass，持久化由调用方负责 | 接入层（server.py）需自行负责读写 |

### 1.3 现有清理机制

- `server.py`：**无清理**（`TMP_DIR` 只写不删）
- `mainLog.ts`：有 `clearLogsCacheFiles()`（清 logs 缓存文件）
- OCR 目录：无清理

## 二、目标存储布局

正式数据根统一为 **`%APPDATA%\assa\`（Electron userData）**；开发期经 `ASSA_DATA_DIR` 环境变量覆盖（主进程启动侧车时注入），保持现有行为不变。**所有数据路径单一收口**：Python 侧车一律经 `resolve_data_dir()`（`ASSA_DATA_DIR` > userData 注入值）。

```
%APPDATA%\assa\                          ← 数据根（userData）
├── data\                                 持久运行时数据（不轻易删）
│   ├── agent\                            Agent 侧车数据
│   │   ├── sessions\                     SessionDB state.db（Phase 2 引入时）
│   │   ├── memory\                       hermes_core 记忆库 core.db
│   │   │                                 + memory_injections.jsonl + memory_autogen.json
│   │   ├── soul\                         soul.json（人格）+ drift 记录
│   │   ├── emotion\                      emotion_state.json + hormones 快照
│   │   └── tts\                          TTS 合成输出（缓存，30 天清理）
│   ├── models\                           faster-whisper-base / kokoro 等本地模型
│   ├── ocr\                              OCR 服务数据（截图临时输入、服务日志）
│   └── wallpapers\                       壁纸视频缓存（30 天清理）
├── logs\                                 主进程日志 + agent 日志 + assa-tools.log 审计
├── cache\                                可安全清理的运行时临时
│   ├── audio\                            in_*.wav 录音缓冲（24h）
│   ├── screenshot\                       截图 / 长截图中间产物（7 天）
│   └── playwright\                       Playwright 浏览器数据（如需）
└── （Chromium Cache / Code Cache / Session Storage 等，Electron 托管，不干预）
```

**开发期等价路径**（`ASSA_DATA_DIR=<repo>/data` 时）：`data/agent/memory/core.db`、`data/agent/soul/`、`data/cache/audio/` …与正式版结构完全一致，便于切换。

## 四、临时文件清理策略

**原则**：`cache/` 启动即清（侧车负责），`data/` 内缓存类定期清（主进程负责），`logs/` 轮转（现有机制扩展）。不留"只写不删"的死角。

| 时机 | 执行方 | 动作 |
|---|---|---|
| 侧车启动时 | `server.py` 新增 `cleanup_cache()` | 删除 `cache/audio/*`（>24h）、`cache/screenshot/*`（>7d）、`cache/playwright/*` |
| 应用启动/退出 | 主进程 | 调用现有 `clearLogsCacheFiles()` 扩展：清理 `logs/*.cache`、过期日志（>30d）、`data/agent/tts`（>30d）、`data/wallpapers`（>30d） |
| 可选定时 | 主进程 cron | 每小时触发一次上述清理（复用现有定时机制） |
| 侧车退出时 | `server.py` | 删除当次会话产生的 `cache/audio/*`（保留 24h 内诊断所需） |

**开发垃圾**：`F:\Work\Create\OCR\` 下 `_ls_*`、`_r*`、`_pip*`、`_cdp*`、`_repro*` 等调试产物（约几十 MB）归档到 `F:\Work\Create\archives\ocr-debug-2026-09\` 或直接删除（需你确认，可能有留档价值）。

## 五、移植清单（搬 / 丢 / 改造）

### 5.1 搬入（vendor 到 `Assa/agent/hermes_core/`）

| 模块 | 内容 | 说明 |
|---|---|---|
| `memory/`（12 文件，约 170KB） | MemoryService / store / fragment / scribe / librarian / archivist / hebbian / decay / knowledge / embedding / learning_scheduler | **核心**。完整记忆生命周期（提取→存储→强化→遗忘→归档→检索） |
| `emotion/`（3 文件） | EmotionState / HormonalSystem / ExpressionEngine | 情绪 + 激素 + 表达 |
| `soul/`（3 文件） | HEXACOPersonality / PersonalityDrifter / SoulFile | 人格 + 漂移 + 持久化 |
| `time/`（3 文件） | CircadianRhythm / Anniversaries / ReunionEngine | 时间感知（可选但推荐） |
| SQLite WAL 安全补丁 | `__init__.py` 中的 pysqlite3 替换逻辑 | 防 WAL-reset 数据损坏，保留 |
| `hermes_constants.py`（可选） | `HERMES_HOME` 环境变量机制 | 若 Phase 2 引入 SessionDB 时需要 |

**依赖面已验证**：以上模块全部 import 仅为 Python 标准库 + 模块内部相对引用（如 `from ..emotion.emotion import PADValues`），**零第三方依赖**，拷入即可运行。

| 内容 | 原因 |
|---|---|

| `stt_server.py` / `voice_services.py` / `cosyvoice_server.py` / `edge_tts_server.py` / `gpt_sovits_server.py` | 语音用 Assa 现有 faster-whisper + kokoro |

## 六、迁移步骤（分阶段，每阶段可独立验收）

- **Phase 1 · 换脑 + 存储收口**（本次）：vendor 四模块 → 路径改造 → server.py 记忆/情绪/人格接线 → 新增清理策略 → 验证（记忆跨会话召回、情绪随对话变化、cache 清理生效）。
- **Phase 2 · 会话检索（可选）**：引入 SessionDB（FTS5），对话历史进 `data/agent/sessions/`，支持全文检索。
- **Phase 3 · 外围归位**：OCR 服务数据/日志迁到 `data/ocr/`，开发垃圾归档；`eIsland_store` 确认后废弃。

## 七、决策点（需你拍板）

1. **记忆库位置**：合并到 `userData/data/agent/memory/core.db`（推荐，与 hermes_core 原生布局一致）；还是沿用 `data/memory.db` 文件名（减少改动，但命名误导）。
2. **模型归属**：`faster-whisper-base`（145MB）随数据放 `userData/data/models/`（推荐，免打包），还是打进安装包资源目录（离线安装即带）。
3. **对话历史（Phase 2）**：是否需要 FTS5 全文检索（决定是否引入 392KB SessionDB）。
4. **开发垃圾**：`F:\Work\Create\OCR\` 下调试产物（约几十 MB）归档还是直接删除。
5. **清理保留期**：audio 24h / screenshot 7d / tts 30d / 壁纸 30d / logs 30d，是否按此执行。
