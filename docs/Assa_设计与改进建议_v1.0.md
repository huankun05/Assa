## 一、总结论

| 维度 | 最大债 | 一句话 |
|---|---|---|
| 体验 | 假流式 + 无端点检测 | 首字延迟 = 整轮推理；语音全靠手动控时长 |
| 记忆/情绪 | 长期记忆 stub、情绪未接线 | Agent「有工具、没脑子」；UI mood 写死 happy |
| 安全/工具 | 双轨 schema + 约 70 个遗产死工具 | 白名单 19 vs 执行器 ~90，权限覆盖不可信 |
| 设计叙事 | 形象落地未完成 | 方向已确认为二次元少女，但设计稿/四态差分尚未接入 UI |
| UI 反馈 | 状态不可见 | 用户不知道「她现在在干什么」 |

**北极星场景（建议锁定，防发散）**

> 「帮我把下载文件夹里这周的 PDF 归到文档库，并告诉我哪些是重复的」

验收链路：`file.search` → 用户确认 → `file.copy/move` → 结果回填大面板 → TTS 简短汇报。  
后续每个 P0/P1 都问一句：**是否推进了这条场景？**

## 二、技术侧需要进一步修改的

### 2.1 优先级最高：体验硬伤

| 项 | 现状 | 建议 | 完成判据 |
|---|---|---|---|
| Ollama 真流式 | 非流式 + 8 字符/20ms 人工切片 | P0b 已有；建议**可独立交付、排在换脑前或同步** | 本地首字 < 1.5s |
| 语音端点检测（RMS） | 无 VAD，手动控录音时长 | 渲染层 `ScriptProcessorNode` 回调加 RMS 静音判停（约 30 行，零新依赖） | 说完 1.5s 内自动发送 |
| TTS/临时文件清理 | `data/tts/`、`data/tmp/` 只写不删 | TTS 改 blob 直放；启动清理 + TTL | 目录不再无限增长 |
| mood 写死 | `AssaTab.tsx` `const mood = 'happy'` | 接 store 真实状态；先用现有 2 态也能「活」起来 | 状态点/表情随阶段变化 |

### 2.2 按 P0b 推进（换脑）

1. **真长期记忆**：hermes_core memory + 中文召回验证（recall@5 ≥ 0.8）
2. **情绪状态机真接入**：`emotion.py` 6 态 → prompt → TTS 语速；UI 同步
3. **工具 schema 单一事实源**：以主进程执行器导出；MCP `annotations` 映射 allow/ask/deny
4. **回归对话集**：20–30 条固定脚本（记忆/情绪/工具/边界），每次侧车改动必跑
5. **70 个遗产工具定案**：删 / 择优登记并补 Python 侧定义——schema 重建的前置条件

### 2.3 容易被忽略但应先做

| 项 | 说明 | 建议 |
|---|---|---|
| **既有 46 红测 + 174 tsc 错误** | 换脑期间无法区分新坏 vs 旧坏 | 换脑前开「测试基线修复」批次 |
| **`app.ts` 2599 行巨石** | 每加一个工具都摩擦 | 不必大重构，按域继续切薄 |
| **LEGAL/品牌残留** | 联系邮箱仍是上游 eIsland | 正式发布前统一一轮；基础设施不可改名项除外 |
| **信任等级无 UI** | `security.trust_level` 只能手改 json | 必须补设置页 UI，否则 L0/L2/L3 形同虚设 |
| **半接入插件** | volume-analyzer / hardware-info-helper | 要么接上，要么从构建与注册一并移除 |

### 2.4 建议落地顺序

## 三、设计方向

### 3.1 设计基因（已有，应坚持）

来源 `DESIGN_STYLE_GUIDE.md`：

1. Apple Dynamic Island 极简骨架（三段式形变）
2. 冷色玻璃面板（深色 + iOS 蓝 + backdrop-filter）
3. 暖色角色注入温度

> **铁律：UI 冷、角色暖。冷暖对冲，永远不要让 UI 和角色都冷、都暖。**

### 3.2 角色形象定案（已确认方向）

**产品方向已确认（见全面调查报告 §3.1 / 任务清单）**：汐月 = **可爱小姑娘，二次元风格**，留形象替代空间。  
像素恐龙是 eIsland 遗产吉祥物，**不是**汐月本人；`agent/persona/assa.md` 中「无形象，靠声音 + 状态点」的表述已落后于产品确认，应随形象落地一并更新。

| 方案 | 结论 |
|---|---|
| **二次元可爱少女（默认）** | ✅ 采用。与 persona、产品定位、冷暖对冲一致 |
| 精致像素小生物 | 仅作历史/eIsland 遗产保留，可作彩蛋皮肤，不做主形象 |
| 抽象光球/声纹体 | 不采用 |

**二次元形象设计 brief（生成/外包时必须遵守）**

| 维度 | 要求 |
|---|---|
| 年龄感 | 少女感、亲和，避免幼态过度或性感化 |
| 发型/发色 | 暖色系为主（琥珀棕 / 蜜桃粉 / 暖金），与冷色玻璃对冲 |
| 瞳色 | 与发色协调的暖色或清透蓝绿（点缀冷色，呼应 iOS 蓝） |
| 服装 | 简洁、现代、带一点点科技感细节即可，避免复杂制服 |
| 画风 | 清爽二次元立绘 / 赛璐璐，线条干净，**不要**厚涂写实、不要 3D 渲染 |
| 构图 | 头像以 **头肩胸像** 为主（hover 60px / agent 74px 可读）；应用图标用头肩 + 圆角底 |
| 表情差分 | 至少 4 态：开心 / 思考 / 困惑 / 聆听；眉眼嘴差异要大，32px 可辨 |
| 背景 | 头像 **透明底**；应用图标深色圆角底 + 角色 |
| 禁止 | 文字、水印、logo、多角色、复杂场景、荧光赛博色、白底烘焙进头像 |

小尺寸对策：岛内默认用简化头肩；完整聊天窗/设置页可用更精细立绘。`AVATAR_IMAGE_MAP` 支持按 mood 换图，无需改组件结构。

**无论形象如何，第一优先是把 `mood` 从写死变成真实状态驱动——没有动态反馈的角色只是贴纸。**

### 3.3 品牌资产规范（本建议落地时）

| 资产 | 路径约定 | 说明 |
|---|---|---|
| 应用图标源文件 | `resources/icon/assa.png`（及后续 ico） | 替换/并列现有 `eisland_*.ico`；打包配置 `electron-builder.json` 同步 |
| Agent 头像（hover 页） | `src/renderer/public/image/agent/xiyue_{happy,thinking,confuse,listening}.png` | 填入 `assaMoodConfig.ts` 的 `AVATAR_IMAGE_MAP` |
| Agent 状态图（岛内紧凑条） | 可映射到同一套或子集 | `agentContentConfig.ts` 的 `PHASE_IMAGE` 可逐步切到 assa 命名 |

风格约束（生成/外包美术时写进 brief）：
- 主体：二次元可爱少女头肩胸像，暖色发色 + 清透表情
- 背景：头像 **透明**（PNG alpha），禁止白底/黑底烘焙；应用图标用深色圆角底
- 线条：干净赛璐璐描边，保证深色玻璃面板上可读
- 表情差分必须在 32px 下仍可区分（眉/眼/嘴）
- 禁止：厚涂写实、3D 渲染、文字水印、复杂背景、多角色

### 3.4 云端路由（产品原则补充）

不要依赖 qwen3-4b 自评复杂度（会系统性偏自信）。更稳：

- **规则优先 + 失败升级**：预计工具轮数 > N、上下文超阈值、本地连续失败 ≥2 次 → 升级云端并记录
- 路由策略用运行数据养出来；模型自评只作辅助信号

## 四、UI 建议

### 4.1 Agent 三态反馈要「可见地活着」（高）

现状问题：mood 写死；状态点有 4 色设计但无真实数据源；用户不知道在干什么。

**改法**：
- 状态点绑定真实阶段：`idle`（绿呼吸）/ `thinking`（蓝慢闪）/ `listening`（红快闪）/ `tool`（黄）
- 副行文案按阶段变化：「在听…」「在想…」「要打开浏览器，确认吗？」
- 岛内 compact 条、hover 页、完整聊天窗**共用同一套状态词典**

### 4.2 工具确认要有统一「许可卡片」语言（高）

双闸门 + 通行证落地前，先定组件范式（可增补进 `DESIGN_STYLE_GUIDE.md`）：

```
┌─────────────────────────────────────┐
│  ⚠ 要我删除这个文件吗？              │
│  D:\Downloads\old.pdf               │
│  将移入回收站，可还原                │
│                                     │
│  [ 允许一次 ]  [ 本会话允许 ]  [ 拒绝 ] │
└─────────────────────────────────────┘
```

- 岛内紧凑版：一行 + 允许/拒绝
- 大面板/独立窗完整版：参数详情 + 通行证时长
- 颜色沿用 `--cap-success` / `--cap-danger` / 警告黄

### 4.3 语音球是招牌交互（中高）

`agentVoiceInput` 已是独立态。建议：
- 接 RMS 后：说完自动收；波形「跳动 → 定格 → 转圈转写」
- 区分空态：转写中 / 识别失败 / 模型加载中（`/health` 加 capabilities 握手可支撑）
- 中期迁 `AudioWorklet`（`ScriptProcessorNode` 已废弃）

### 4.4 大面板空状态统一（中）

工具箱/邮件密度高，待办/备忘录相对空。建议：
- 统一空状态：插画位（可复用角色表情）+ 一句引导 + 一个主按钮
- hover Tab = 预览 + 快捷动作；expand 进同一页完整版，避免两套布局

### 4.5 设置独立窗秩序（中）

- 左侧固定导航 + 右侧内容，宽度稳定
- **安全相关单独一组**（权限、通行证、审计、数据导出），与「外观/动画」拉开
- 补信任等级 UI（见 2.3）

### 4.6 冷暖对冲 Code Review 条目（持续）

> 任何新增 AI 相关界面，必须有至少一处暖色角色反馈（表情/光晕/状态色），禁止纯冷玻璃空面板。

### 4.7 浅色主题抽查（低但易翻车）

截图/翻译/贴图浮窗的 `--cap-*` 偏 dark-only。建议 light 下走一遍，补 `[data-theme='light']` 覆盖。

### 4.8 清理死 UI（低）

volume-analyzer、hardware-info-helper、`AiSettingsSection`、11 个死 IPC——要么接上，要么删干净。半成品比没有更伤信任。
