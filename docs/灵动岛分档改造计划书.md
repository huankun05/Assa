# 灵动岛分档改造计划书

> 目标：按窗口像素尺寸把灵动岛分为多档，逐档确定"装什么、不装什么"，让每档职责清晰、互不打架。
> **最终档位模型**（经逐档讨论收敛）：3 个主尺寸（胶囊 260×42 / hover 500×60 / 大面板 860×150·860×400）+ 1 个事件临时态（通知条 500×88）+ 独立窗口/浮窗（设置 / 聊天 / 邮件 / 翻译 / 工具箱 / 计算器）。原设想"五档"在讨论后合并为 3 档（860×150 与 860×400 同属大面板档的两种高度；500×88 通知条不作独立档）。
> 讨论方式：每档先给"现状 → 推荐 + 原因 → 待确认点"，确认后定稿进本计划书，再讨论下一档。
> 当前进度：第一档、第二档、第三档均已定稿完整。贯穿原则 A/B/C/D + B-2（小应用浮窗）齐备；默认配置与 4 阶段实现方案落实；档位模型 = 胶囊(260×42)/hover(500×60)/大面板(860×150·860×400) + 事件临时态(500×88 通知条) + 独立窗口/浮窗(设置/聊天/邮件/翻译/工具箱/计算器)。可进入实现。

***

## 第一档：胶囊（260×42 / idle 态）

### 定位

常驻、鼠标穿透的默认形态。鼠标靠近即变为第二档（hover）。**只做"一眼扫过就有用"的展示 + 紧急提示，不做任何操作/编辑/详情。**

分工原则：

- 第一档 = 紧急提示 + 当前状态（告诉你"现在有什么事"）

- 第二档（hover）= 快速操作 + 详情预览（让你"动手"）

### 推荐内容

**左侧（常驻）**

- 时间（主）+ 日期（次，缩小变淡，不与时间抢 C 位）

**中部「当前焦点」（每刻只显示 1 项，按优先级互斥）**

| 优先级 | 触发条件                        | 显示内容                        |
| --- | --------------------------- | --------------------------- |
| 1   | 倒计时 / 番茄钟 **正在运行**          | 剩余时间 `MM:SS`（仅进行中显示，暂停不显示）  |
| 2   | 有未读通知（邮件 / AI / 系统告警，见下方接口） | 通知徽章：图标 + 未读数字              |
| 3   | 音乐 **正在播放**                 | 小音符 / 波形（右侧已有封面时可省略）        |
| 4   | 默认无以上状态                     | 天气图标 + 温度（如 `☀ 27°`，去掉描述文字） |

**右侧（播放时）**

- 专辑封面（仅播放中 + 有封面）

### 发光 / 变色规则

- **发光**：仅音乐播放 + 有封面 + 开启"音乐外发光"时触发（灵动岛标志性氛围，不滥用）。

- **变色 / 脉冲**：通知徽章分两档——

  - 普通未读（邮件、AI 消息）：**静态小红点 + 数字**，克制不抢注意力。

  - 紧急 / 系统告警（如同步失败、重要提醒）：**呼吸灯（轻微脉冲）**，仅在真紧急时吸引注意。

- 倒计时/番茄钟默认不变色；最后 1 分钟可后续扩展为数字变红（本期不做）。

### 通知徽章接口（预留，不急着完全实现）

现状只有"单条弹出式通知"（`NotificationData`），没有"胶囊未读计数"。需新增一个轻量、可扩展的源注册机制，让未来邮件 / AI / 其他消息都能推到胶囊，且互不影响：

```ts
// 建议新增类型（计划书阶段定义，实现时落地）
type NotificationBadgeSource = 'mail' | 'ai' | 'system' | (string & {}); // 留扩展位，未来新增源只需加联合成员

interface BadgeState {
  source: NotificationBadgeSource;
  count: number;          // 未读数
  urgent: boolean;        // true=呼吸灯，false=静态红点
  icon?: string;          // 可选自定义图标
}

// store 形态：按源聚合未读
// badges: Record<NotificationBadgeSource, BadgeState>

// 胶囊读取：取 count>0 中优先级最高（urgent 优先，其次 count 大）的一个做展示
// 接口函数（预留）：
//   setBadge(source, count, urgent?)  —— 各数据源上报
//   clearBadge(source)                —— 进入对应详情后清零
// 主进程推送：ipcRenderer.on('badge:update', ...) 预留通道
```

- **本期落地范围**：仅写接口 / 类型 / 空 store + 胶囊读取与渲染占位（有 count>0 即显示徽章）。真实数据源（邮件 IMAP 轮询、AI 消息监听）后续单独排期接入，不阻塞第一档 redesign。

- **扩展方式**：未来新增消息源只需 `setBadge('xxx', n)`，无需改胶囊代码。

### 待确认项（已闭环）

- 天气降级为"图标+温度"：**已确认采用**。

- 通知接口骨架：**用户要求先写接口占位**（类型 + 空 store + 胶囊渲染占位），不急着完全实现真实数据源，本期预留即可。

## 贯穿所有档的设计原则（已确认）

第二档讨论中用户提出了一套系统性想法，以下原则贯穿全部五档，是本次改造的底层架构，而非某一档独有。

### A. 页面可配置化（顺序 / 显隐 / 创建）

- 页面导航顺序、显隐可在设置中**拖拽调整**。

- 用户可**自主创建自定义页面**：本期提供 2 种轻模板——「内嵌 URL（填网址）」「空白组件容器（拖入已有小组件）」，不做重的可视化拖拽编辑器。

- 「内容也可编辑」明确为**布局级**：页面内小组件可增删 / 拖拽排序；**不做内容级**（改文字 / 逻辑）。

### B. 控制中心浮层（第二档 time 页交互范式，可推广到其他档）

- 常驻**可配置按钮栏**（在设置中勾选哪些常用按钮出现）。

- 点击按钮 → 上方 **popover 浮层**：左=按钮图标，右=该按钮操作（如音量滑块）。

- 浮层 hover 内不收，鼠标离开浮层自动缩回（"放开就缩回"）。

- 浮层与窗口是**两层 dismiss**，互不打架。

### B-2. 小应用浮窗模式（按钮触发的"完整小工具"）

- 某些按钮不是"滑块式操作"，而是**打开一个独立小应用**（如计算器、翻译、工具箱）。它们以**浮窗**形式盖在当前快捷面板之上，而非挤进灵动岛尺寸。

- 浮窗内是完整小应用 UI；点击浮窗的**退出键 / 关闭按钮 / ESC** 即关闭浮窗，**返回到之前的快捷面板**，不丢失面板上下文。

- 浮窗复用 `StandaloneWindow` 架构（或轻量 overlay 窗口），与设置/聊天/邮件/翻译/工具箱同源。

- 归属清晰：**控制中心是"入口"，浮窗是"运行时"**；小应用不在灵动岛任何档内常驻，用完即退。

- 已确认的浮窗小应用：计算器（用户举例）、翻译、工具箱；后续可从按钮池增其他。

### C. 滑动翻页（手势）

- 支持**鼠标按住拖拽**翻页。

- 支持**鼠标滚轮横向 / 触控板双指横扫**（Windows 映射为 `wheel` 事件 `deltaX`）翻页。

- 翻页手势只在面板根容器生效；浮层内滚动 `stopPropagation` 防误翻。

- 左右边缘显示"可翻页"指示（小箭头 / 高亮）。

### D. 展开 / 收起行为分层

- **第一档（胶囊）**：靠近出现，离开自动缩回（保持现状，符合"路过看一眼"）。

- **第二档及以上（hover / expanded / maxExpand）**：靠近展开后**常驻**，仅**点击窗口以外区域**才收回（click-outside dismiss + blur）。

### 确认点（用户已拍板）

- 自定义页面模板：先只做「内嵌 URL」+「空白组件容器」两种（轻量）。

- 翻页手势：拖拽 + 滚轮/触控板横向，**都要**。

- "内容可编辑"范围：仅布局级（小组件增删拖拽排序），不做内容级。

## 第二档：Hover 半高横条（\~500×60）

### 定位

鼠标靠近即出现，**展开后常驻直到点外部**（遵循原则 D）。是"轻操作面板"——快速操作 + 详情预览。
本档在讨论中经用户 refinements 重构：**控制中心纯按钮化、歌词居中 + 喜欢、番茄钟独立页、AI 语音/文字双态**。

### 结构（基于贯穿原则）

- 左侧导航点列（顺序/显隐可配置；第一个点=前一级入口、最后点=进后一级）：`time / lyrics / weather / assa / pomodoro / expand`

- 「管理页面」「设置」**并入 time 页控制中心按钮池**（不再作为右侧常驻/导航列底部工具栏，翻页后不残留）

- `time` 页 = **纯控制中心**：只放可配置控制按钮（不含倒计时编辑、不含当前时间/农历），点击按钮→浮层操作（原则 B）

### 各 Tab 定稿（含本次 refinements）

| Tab          | 决定                                                                         | 原因                                                                |
| ------------ | -------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **time**     | **纯控制中心**：只放可配置控制按钮（隐藏/退出/亮度/音量/截图/任务管理器…），**不含倒计时编辑、不含当前时间/农历显示**         | 用户要求本页只做按钮；倒计时与时间已移到专用页（pomodoro / 第一档常驻），保持"操作面板"纯粹；后续可从按钮池增其他按钮 |

第二档（hover）默认渲染 6 个 Tab，每个 Tab 开箱即包含以下内容（基于当前代码现状，后续"按钮池 / 页面顺序"在设置里可调）：

**② lyrics（歌词页）—— 居中重构**

- 中部**居中区**：未播放 = **封面（36×36）与歌名/歌手并排**（flex row，封面在左，文字在右上下两行）；播放 = 居中显示**歌词**，隐藏封面/歌名/歌手

- 右侧控制：`喜欢♥` + `上一曲 / 播放暂停 / 下一曲`（♥ 在三按钮左侧，留 14px 间隔；未播放时禁用，喜欢随播放可用）

- 背景：音乐**起伏波纹**（播放时随音频幅度动，`HOVER_MUSIC_BG_STYLE` 增强；保留 silky/wave 两种）

- 对接：歌名/歌手/封面/喜欢来自音乐软件 —— 先对接**网易云音乐**，统一到现有 `MediaState` 接口（喜欢♥ = 红心/取消，调用其 like API）；未播放显示占位

- 注：播放中第一档只显示音符/剩余，不重复歌词

**③ weather（天气页）—— 已优化**

- **整体居中**：天气主体在 hover 条 500×60 内水平居中

- 左区：当前天气大图标（36px，**点击刷新**）+ 图标下方天气简述

- 中区：温度大字（30px，独占高度）+ 位置块（城市 + 经纬度，贴温度右侧，居中对齐）

- 右侧：未来两天预报（星期 / 小图标 / 天气简述 / 平均温度）—— 已砍降水概率和风速

- 数据源：IP 定位城市 → Open-Meteo / UAPI（设置可切数据中心）

- **刷新机制**（4 级触发 + 节流保护）：

  - 应用启动时拉一次

  - 切换到 weather tab 时自动拉一次（5 分钟节流）

  - 30 分钟定时自动刷新（被节流兜底）

  - **手动点击大图标强制刷新**（跳过节流）→ 图标旋转动画（0.7s 匀速）→ 成功/失败 toast 提示（2 秒自动消失）

- 节流策略：非强制刷新时距上次成功拉取 < 5 分钟则跳过；`lastRefreshAt` 记录于 store

**④ assa（汐月 AI 页）—— 双态**

- **静默态**：居中「汐月 AI」入口按钮 + 提示"点击进入对话"（点击→开独立聊天窗口）

- **语音态（二档 overlay）**：声纹/律动背景 + 顶部**转写文字横条**（实时 ASR 文本流式显示）+ 整岛**发光脉冲**；说完自动收或转文字态

- **文字态**：点击语音态/入口 → **打开独立聊天窗口**（StandaloneWindow 模式，复用设置独立窗架构），不占用灵动岛尺寸

- 触发：assa 页麦克风键 / 全局语音热键 → 进语音态

**⑤ pomodoro（番茄钟页）—— 新增**

- 编辑：工作/休息时长（时:分:秒）、标签

- 控制：开始 / 暂停 / 重置、循环开关（自动 工作↔休息）

- 运行中：第一档中部显示剩余 `MM:SS`；本页显示进度环

- 数据：本地存储历史/统计（后续）

**⑥ expand（展开页）—— 不变**

**可配置维度（全部在设置窗口「面板与页面」分类调节，非 hover 内）**

## 第三档：大面板（maxExpand，860×400）— 用户指认的"第三种大小"

### 定位

用户确认：截图中的大面板即**第三种大小**，是 island 最大的常驻形态，承载多页工具 / 信息面板。
代码对应 `maxExpand`（860×400）；hover `expand` 直接落点为 `EXPANDED_FULL`（860×150，紧凑版）。
二者可视作**同一档的两种高度**（紧凑 150 / 完整 400），由内容决定，**统称"大面板档"**。
收起行为遵循原则 D：展开后常驻，点窗口外才收。

你明确要求：**"设置页面要只有一个设置，没有其他杂七杂八"**。因此设置窗口不再承载任何"应用功能"或"工具集合"。
