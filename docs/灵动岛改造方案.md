# 汐月 · 灵动岛改造方案（基于 Apple HIG + eIsland 调研）

> 调研对象：Apple 官方 Dynamic Island 设计规范（WWDC23 / HIG Live Activities）、
> 开源项目 eIsland（Electron+React 的 Windows 灵动岛，GPL-3.0，仅借鉴设计不抄代码）。
> 目标：把 汐月 Phase 0 的"固定大黑卡 / 简易胶囊"升级为真正有苹果质感的 morph 灵动岛。

---

## 一、调研结论：真正的灵动岛由 4 个技法叠加而成

| 技法 | Apple 做法 | eIsland 实现 | 汐月现状 |
|---|---|---|---|
| **1. 弹簧形变** | "deliberate elasticity，像活体生物"；展开/收拢有过冲回弹 | `width/height` 的 CSS transition（缓动 `cubic-bezier(.22,1,.36,1)`）+ 叠加瞬时 `morphing` 类的 `scale()` 关键帧脉冲（过冲→回落） | 只有 transition，**无过冲脉冲**，显得"死" |
| **2. 鼠标穿透** | 岛浮在最上层，但空闲时不挡桌面 | 主进程 `setIgnoreMouseEvents(true,{forward:true})` 按状态切换（`STATE_CONFIGS.mousePassthrough`） | 靠"缩小窗口到胶囊大小"间接穿透，胶囊本身仍挡点击 |
| **3. 状态配置表** | 三尺寸级 Minimal/Compact/Expanded + 每态独立尺寸 | `STATE_CONFIGS`：每态有 `mousePassthrough / expanded / enterDelay / leaveDelay` + `ISLAND_STATE_AREA`（面积驱动尺寸） | 只有 `phase + chatOpen` 两个布尔，无配置表 |
| **4. 悬停预览 + 点按层级** | 长按→Expanded，点按→打开 App 对应位置 | hover（带 60ms 进入延迟）预览 → 点击→expanded → 再点→idle；50ms 轮询 `isMouseInWindow` | 仅点胶囊 toggle 展开，无 hover 预览 |

**苹果额外硬规则（必须对齐）**：
- 黑色不透明底 + 品牌色只做点缀（图标/进度/强调），不铺满背景；浅色文字。
- **同心圆放置**：圆角元素嵌套、四周均匀留边；内容质心嵌在岛壁内，别戳角落。
- 内容更新/布局变化要**让已有元素平移到新位置**（保留连续性），不要消失重来。
- 动画 ≤2s；岛只放"一瞥即懂"的信息，复杂交互交给主窗口。
- Compact 级要**紧凑贴合、不留空隙、体现身份**。

eIsland 的具体数值（可借鉴的比例，非抄代码）：
- 基础胶囊 `260×42`；hover `500×60`（仅圆下角，向下展开成下拉）；expanded `860×150`；maxExpand `860×400`。
- 动画速度档：slow 1.08s / medium 0.68s / fast 0.34s（均为 `cubic-bezier(.22,1,.36,1)`）。
- 细节：`.island-shell::before` 斜向高光；`island-bg-layer` 背景层（图片/视频，opacity 过渡）；`music-glow` 主色光晕。

## 二、现状审计（汐月当前实现）

现有 `src/App.tsx` + `src/index.css` + Rust `set_island_size`：
- ✅ 已做：胶囊→展开 morph（transition 缓动曲线正确）、玻璃拟态、听/想/说声波/加载动画、窗口随形态 resize。
- ❌ 缺：弹簧过冲脉冲、真正的鼠标穿透（胶囊挡点击）、状态配置表、hover 预览、速度档、同心圆布局细节、`::before` 高光/光晕。

**结论**：骨架方向对，但"苹果质感"差在①没有弹性过冲、②空闲时胶囊仍吃点击、③状态模型不可扩展。

## 三、改造方案（分相，自底向上）

### Phase A — 弹簧形变（最高性价比，低风险）
**目标**：morph 从"平滑缩放"升级为"弹性活体"。
**改动**：
- `src/App.tsx`：引入 `prevStateRef` + `morphing`/`fromState` 状态。状态变化时置 `morphing=true` + `fromState=prev`，过 `MORPH_DURATION`（默认 medium 680ms）后复位（直接照搬 eIsland `useDynamicIslandShell` 的套路，但用 汐月 的 phase 体系）。
- `src/index.css`：
  - `.island.spring` 用 `cubic-bezier(.22,1,.36,1)`，时长默认 `.68s`（比现在 .5s 更"压得住"）。
  - 新增关键帧 `islandMorph`（轻微 scale 过冲：`scaleX/scaleY` 在 1±0.03 间回弹）、`islandExpandFromIdle`、`islandShrinkToIdle`，由 `.morphing.from-<prev>` 触发。
  - 速度档 `.speed-slow / .speed-fast` 改 transition 时长（1.08s / 0.34s）。
- 窗口 resize 逻辑不变。
**风险**：纯前端 + CSS，零 Rust 改动，可独立验证。

### Phase B — 真正的鼠标穿透（对齐 Apple "浮在最上层但不挡"）
**目标**：idle 时整颗胶囊连点击都穿透桌面，唤醒靠热键；active/expanded 才接管鼠标。
**改动**：
- `src/App.tsx`：引入 `STATE_CONFIGS`（汐月精简版），每项含 `passthrough` 布尔。状态变化时调用
  `getCurrentWindow().setIgnoreCursorEvents(cfg.passthrough)`（来自 `@tauri-apps/api/window`，**无需新增 Rust 命令**）。
  - `idle` → `true`（穿透）；`listening/thinking/speaking` → `false`；`expanded(chat)` → `false`。
- 保留 `set_island_size` 的窗口 resize（窗口仍跟随胶囊，双重保险），但穿透改由 `setIgnoreCursorEvents` 负责——语义更清晰，且 idle 时即使胶囊区域也能点穿。
**风险**：低。需注意——idle 穿透后胶囊不可点，唤醒/展开一律走热键与 tray（已具备）；想看历史对话则按热键说话或点 tray"显示面板"。

### Phase C — 状态配置表 + 悬停预览（Apple "长按/点按层级"桌面版）
**目标**：鼠标移到胶囊上延迟展开一小段"预览"（如最近一条回复摘要），点击才全展开；离开延迟收起。
**改动**：
- `src/App.tsx`：加 `enterTimer/leaveTimer`（用 `STATE_CONFIGS` 的 `enterDelay/leaveDelay`，默认 60/80ms）。hover 进→`setHover` 预览态（胶囊加宽到 ~300×46 显示摘要）；hover 出→`setIdle`。
  - 因 汐月 是语音助手，hover 预览**可选**；若觉得多余可只保留"点胶囊 toggle 展开"。
- 点按层级：`idle` 点→`hover/expanded`；`expanded` 点→`idle`（沿用现有 `toggleChat`）。
**风险**：中。需处理"热键唤醒"与"hover 预览"的冲突（唤醒时直接进 active，跳过 hover）。

### Phase D — 苹果材质打磨（视觉收口）
**改动**（`src/index.css`）：
- 加 `.island::before` 斜向高光（`linear-gradient(135deg, rgba(255,255,255,.05), transparent, rgba(0,0,0,.1))`，opacity 过渡）。
- `backdrop-filter` 提到 `blur(20px) saturate(180%)`（更接近 iOS 材质）。
- `speaking` 态加 `box-shadow` 外发光（ accent 色），强化"在说话"的活体感。
- **同心圆修正**：胶囊内 `padding` 改为均匀留白；圆角子元素（状态点、声波条）用 `concentric` margin 不戳边角；消息气泡在 expanded 内保持均匀内边距。
- 可选：背景层（壁纸感知 tint）——Phase 1 再议，先不引。

### Phase E — 可扩展状态模型（为未来留接口）
**目标**：把"计时器 / 音乐 / 通知"等未来迷你态变成 `STATE_CONFIGS` 的一行配置，各自尺寸，不动核心。
**改动**：`STATE_CONFIGS` 预留 `timer`/`music`/`notification` 条目（含面积/穿透/延迟），核心 morph 逻辑通用。未来加功能只填配置 + 一个渲染分支。
**风险**：低（本相只是把结构铺好，不实现新功能）。

### Phase F — 控制中心（灵动岛快捷开关面板）（待实现）
**目标**：让用户自定义哪些快捷功能常驻显示在灵动岛中，实现类似 iOS 控制中心的快速操作体验。
**设计定位**：
- **控制中心是设置页的一栏**（`SettingsTab` 内的一个 settings section），而非独立窗口或独立页面。
- 控制中心内部是**快捷功能开关列表**（如：显示模式、鼠标穿透、置顶、截图、静音等），用户可以选择哪些功能常驻显示。
- 选中的快捷功能会在灵动岛的 hover 态（底部工具栏）和/或 expand 态中显示为快速操作按钮。
**交互流程**：
1. 用户在设置页「控制中心」栏中勾选/取消快捷功能
2. 选中的功能以图标按钮形式常驻在灵动岛底部工具栏（hover 态）或展开面板
3. 点击灵动岛上的快捷按钮直接执行对应操作（无需进入设置）
**待实现内容**：
- 设置页新增「控制中心」section（包含快捷功能开关列表）
- 灵动岛 hover 态底部工具栏支持动态渲染已选中的快捷按钮
- 快捷按钮点击执行对应操作（通过 IPC 调用主进程功能）
- 快捷功能配置持久化到 store
**风险**：中（涉及设置页新增 section + 灵动岛工具栏动态渲染 + IPC 扩展）。

## 四、推荐执行顺序 & 待定决策

**推荐先做 A + B**（一次提交）：直接拿到"弹性 morph + 真穿透"，苹果质感跃升且风险极低。
C / D 视手感再加；E 顺手铺。

**需要你拍板的几点**：
1. **Phase C 悬停预览**要不要？（语音助手其实热键为主，hover 预览可能多余）——我倾向**先不做 C**，保持"热键唤醒"的纯净路径。
2. **穿透默认行为**：idle 全穿透（连胶囊都点穿，只靠热键/tray 唤醒）是否符合你的使用习惯？还是希望 idle 胶囊**可点**展开历史（那就只在"完全无消息且 idle"时穿透）？
3. **动画默认速度**：medium 0.68s（推荐，最稳）还是 fast 0.34s（更跟手）？
4. 方案确认后，我按 A+B（+ 可选 D）直接改 `src/App.tsx` / `src/index.css`，Rust 端**无需改动**（穿透走前端 `setIgnoreCursorEvents`）。
