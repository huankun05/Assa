# 长截图（滚动拼接）功能问题排查记录

> 记录 Xiyue 长截图功能在 2026-09-07 ~ 09-08 调试过程中遇到的问题、根因与修复。
> 范围：渲染端 `resources/capture.js` + `resources/capture.css`、主进程自动滚动 IPC、编辑器窗口渲染。
> 关联文档：`docs/汐月Electron版现状.md`
> 版本标记：r19 ~ r38（一轮修复记一个 r 号，便于回溯）。

## 一、功能现状

长截图采用「主屏可见 + 自动匀速滚动 + 静止抓帧 + 帧-累积匹配 + DP 最小能量缝拼接」的桌面主流方案
（与 ShareX / eSearch 同源，非录屏式）。数据流：

```
主进程捕获（koffi GDI BitBlt+GetDIBits）
  → 渲染端 lsMatchScroll 帧-accum 匹配
  → lsAppendRows 整数 1:1 拼装 + DP 最小能量缝
  → 编辑器预览 → cropLongShotFull 1:1 导出 PNG
```

截至 r38，三类最显眼症状（画质模糊 / 接缝横线 / 蓝色边框残留）代码层均已修复；
拼接几何在 r26 高选区与 dwarf 矮选区真实帧 E2E 上总高精确命中。r38 之后尚未经用户实测闭环。

## 三、详细排查

### 3.1 画质模糊（问题 #1）

**现象**：用户多次截图反馈长截图编辑器内整图发虚，但导出 PNG 本身是清晰的。

**根因（r27 实锤）**：用 CDP `Page.captureScreenshot` 抓取编辑器窗口合成输出，与源图逐像素对比（mse=0 判 1:1）。
- 若编辑态发生 setBounds 缩放（如 1708×920 → 946×920），渲染输出 lap_var 永久掉到原图 31%；
- 软件合成（--disable-gpu / SwiftShader）下 resize 后栅格尺度停留 1.0、再放大输出 → 整窗发虚。
- 用户自 r22 编辑器存在以来看到的「模糊」全部是这个，导出 PNG 实际清晰。

**附带澄清**：此前「运动模糊」「遮罩压暗」等理论在真实帧上被证伪（同内容配对误差极低、帧间对齐整数精确）；
顶部「横线/半透明带」是聊天窗 SVG 卡片自身渐变设计，非拼接瑕疵。

**修复**：
- r27：尺寸已满足 → move-only 保持原尺寸；需缩放 → 屏外改尺寸 200ms 后挪回；闭环自愈（主进程 900ms 后实测 lap_var 比值 <0.7 → hide/show 重建合成表面）。
- r28：sharp-guard 守卫固定取图顶部居中，聊天窗顶部纯背景 lap=0 导致守卫整体跳过 → 改为扫描 5×N 候选取 lap 最大区。
- r29：缩小 resize 也是触发器 → 窗口已 ≥ 目标尺寸走 move-only；编辑态 canvas 加 `image-rendering:pixelated`；自愈从 hide/show 改为 `webContents.setZoomFactor(1.001)` 抖动后回 1.0。

**验证**：CDP 抓窗口合成输出逐像素对比，mse=0 判 1:1。

### 3.2 接缝横线（问题 #2）

**现象**：拼接处出现一道明显横线 / 半透明带。

**根因**：早期用 6→12 行线性羽化带（alpha 渐变）做接缝融合。全景拼接文献（PicLab / Springer）明确反对宽线性羽化带——
低频亮度差发虚、高频边缘出重影，即这道横线成因。

**修复（r32）**：删掉羽化带，改用内容感知 DP 最小能量缝——在名义缝 ±2 行内逐列用 DP 找使「缝上/缝下」像素差最小的垂直线，
沿缝硬切 + 仅 1px 淡化（无宽渐变带）。无横线、无发虚。

### 3.3 拼接错位 / 重复（问题 #3）

**现象**：拼接后内容重叠、错位、重复出现。

**根因（r37 / r38 用真实帧 manifest 取证）**：
- 第一格位移过大/过小污染速度基准：固定初始 `delta=-60` 在用户 App 滚动系数下，某些选区首格滚 509 行（重叠仅 31 行）或滚 95 行（重叠 72% 内容重复）。
- 周期内容假谷：聊天 / 列表 / 代码块等内容呈周期性，seed 模式（accept<2）完全跳过速度先验，把内容周期假谷（如 160）当真位移接受，后续错位累积。

**修复**：
- r37：`isSeeding` 收紧（有可信基准即退出 seed 启用速度先验）、`velBound=max(20, lastGoodS*0.3)`、强谷豁免在矮选区不再豁免速度约束、初始 delta 自适应预估。
- r38：初始 delta 固定回 -60（r37 的 0.055×帧高预估在部分 App 系数下算出 -19 致首格仅滚 95）；seeding 候选加向 0.5×帧高软偏好，防周期内容锁假谷。

### 3.4 拼接全盘乱（问题 #4，历史）

**根因**：
- r26：r25 废弃 `const BIN` 但 best-guess 细搜仍引用 `bestSB*BIN` → 死引用 ReferenceError 整帧丢失。
- r26：采样列子集 stepX=w/160≈9px 在浅误差曲线上翻转真假谷（真实帧 f0005：stepX=9 下伪谷 68 < 真谷 422）。
- r28：静止判据 `e0<0.3` 是视频帧时代遗产，GDI 同内容重抓 e0 实测 87~1061 → 静止帧漏过 → 粗搜找假谷。

**修复**：BIN 死引用修为 bestSB±4；全分辨率 stepX=2 扫描 + 谷检测 + top-4 细搜；
GDI 静止判据改为 `e0<2500 && frameDiff<=0.5` → skip 不计拒链；effR 速度加权仲裁替换裸 evalR 终审。

### 3.5 蓝色边框残留（问题 #5，UI bug）

**现象**：长截图编辑器内四周出现蓝色带白边方框 + 白色 resize 手柄。

**根因**：`.capture-mask-frame`（选区高亮框）在长截图编辑态未被正确隐藏；
`enterLongShotEditor` 设 `display:none` 后 `drawMask()` 经 `layoutHandles(true)` 又把手柄显示出来；frame 本身仍定义蓝色 border/outline。

**修复**：
- r34：`body.is-longshot-edit .capture-mask-frame { display: none !important; }`。
- r35：`drawMask()` 的 `layoutHandles(...)` 加 `&& !document.body.classList.contains('is-longshot-edit')`，编辑态永不显示手柄。
- r36：`.capture-mask-frame` 的 `border:none; outline:none;`，`body.is-longshot .capture-mask-frame` 同样去蓝边。普通 / 长截图都不再有蓝框。

### 3.6 零拼接（快滚，问题 #6，历史）

**现象**：快速甩滚时 matches:[] 零接受，整段丢失。

**根因（r20 实锤）**：用户快速甩滚单帧位移 388~405px，重叠仅 26~41 行，被重叠下限 normalMinOverlap=60 全拒。

**修复**：r20 种子级接受 + 深谷豁免重叠下限；r21-r23 改「自动匀速步进制滚动」（单格滚轮 → lsWaitQuiet 判静止 → 抓帧），
每格位移恒定 ≈50% 帧高、重叠恒足，从源头不拒拼。

## 四、验证方法（沉淀）

- 语法：`node --check resources/capture.js`
- 渲染端加载 / 按钮绑定：`_vm_load_check.js`（真实执行 capture.js，16/16）
- 匹配器回归：`_matcher_check.js`（11/11）
- UI 视觉测试：`_ls_edit_visual_test.js`（Playwright + 真实 Chromium，注入 electron/process 垫片，进入编辑态截图 + 计算样式断言 + 人工看图）
- 拼接几何 E2E：提取生产 `lsMatchScroll` 真实源码 + 用户真实会话 `ls_<t>_manifest.json` 帧喂入，比对帧-帧 SSD 真值与接受值
- 清晰度：CDP `Page.captureScreenshot` 抓窗口合成输出，与源图逐像素对比

## 五、残留风险

1. 矮选区重叠下限 60 行（≈11% 帧高）偏紧，极低噪声页仍可能拒拼 / 锁错。
2. 周期内容假谷在极低噪声页仍可能被 seed 接受。
3. r38 首格固定 delta=-60 在 App 滚动系数差异大时可能仍需调。

**下一步**：若用户仍报拼接不准，取 `%LOCALAPPDATA%\Temp\xiyue-ls-debug\` 下最新 `ls_<时间戳>_manifest.json` 继续取证；
备选项：重叠下限放宽到 0.25、UI Automation 读 ScrollPattern 实测滚动分数。
