### 1.5 多平台策略（A+B）

**A（现阶段）**：官方支持面仅 Windows；README 可写「架构为未来扩展预留」，不承诺 mac/Linux 发行物。  
**依据**：`LICENSE` 附加条款禁止针对 Apple macOS / 任何 Apple 操作系统的移植与再分发；只要代码含 eIsland 血统即受约束。Linux 为灰色地带，但保留声明期间不正经宣称支持。

**B（工程纪律，现在只立规矩、不重构）**：

| # | 纪律 | 性能影响 |
|---|---|---|
| B1 | 新系统能力只写壳侧（`src/main` + `plugins/*`） | 无 |
| B2 | core 对外只走工具协议（现有 HTTP / tool schema） | 无 |
| B3 | 不把 UI/窗口逻辑塞进 `agent/` | 无 |

明确**不做**：为假想跨平台提前抽通用插件抽象层。

**后期真要多平台时的路径**：

| 资产 | 复用性 |
|---|---|
| `agent/`（编排/记忆/路由/人格）、工具 schema、双闸门策略、persona、i18n、形象资产 | ✅ 基本/全部复用 |
| Electron UI、14 个 Windows 插件、打包常驻托盘 | ⚠️/❌ 需按平台重写或重做 |

规模预期：**复用 core + 单新平台壳 + 能力子集 ≈ 数周～2–3 个月**；不承诺三端齐发。现在守 B 约省后期 20–30% 迁移成本，当前成本为零。

## 2. 议题二：产品主体 = 工具箱 + 本地 AI（隐私优先的轻量助手）✅ 已决

**拍板日期**：2026-09-11

### 2.1 决议摘要

| # | 决议 |
|---|---|
| D6 | 主叙事：**工具箱 + 本地 AI**；不做「全能力管家」承诺；本地 AI 卖**隐私** |
| D7 | **铁律一**：AI 可整体关闭，工具箱不残废；关闭后侧车/模型进程不启动 |
| D8 | **铁律二**：组件三档（Core 必装 / AI Pack 可选下载 / 扩展可选包）；模型走可选下载渠道，用户自选是否安装 |
| D9 | **铁律三**：数据密级 D0–D3 × 通行证（静默观察/谨慎助手/熟练助手/完全托管，内部代号 L0–L3）；D3 默认永拦；**与工具权限共用通行证，单一事实源，防重复与漏洞** |
| D10 | 通行证设置 UI 必须落地（替换手改 json）；**无默认遥测** |
| D11 | 对外主口径：「本地 AI 灵动岛：看一眼就知道，说一句就办好；模型不离机，角色随你开。」（综合稿见 §5） |

### 2.2 铁律一（原文）

AI 关闭后（角色模式切到**纯工具**）：灵动岛/歌词/天气/工具箱/系统控制/网易云等**全部照常**；无「AI 加载中」类半残状态；侧车与模型进程可完全不启动。第一期功能均按「AI 挂了也能用」设计。

> 与 D22 对齐：不再另设「AI 总开关」；**纯工具 = 关 AI**。

### 2.3 铁律二：组件分层（D8）

| 档 | 内容 | 默认 | 用户 |
|---|---|---|---|
| **Core 必装** | Electron 壳、灵动岛、工具箱、插件、规则层、设置 | 安装即有 | 不可卸 |
| **AI Pack 可选** | 本地模型（STT/TTS/LLM）及推理依赖 | 默认不装或首启轻提示 | 设置页一键下载/卸载，标明体积与效果 |
| **扩展可选包** | 后续实验功能 | 默认关 | 同左 |

交互：首启引导说明三档；未装 AI Pack 时语音入口引导下载、工具路径零骚扰；卸载 AI Pack 后回铁律一状态。

### 2.4 铁律三：数据密级 × 通行证（D9）

**两个正交维度，共用一张通行证**：

| 维度 | 管什么 | 来源 |
|---|---|---|
| 工具权限 | 能不能**动手** | 已有信任等级 + 双闸门，语义不变 |
| 数据密级 | 能不能**看见/说出/写入记忆** | 本议题新增读侧语义 |

**通行证命名对照（全文统一；用户可见用中文名，代码内部可用 L0–L3）**：

| 内部代号 | 用户可见名 | 简述 |
|---|---|---|
| L0 | **静默观察** | 只聊，几乎不动手、几乎不看私有数据 |
| L1 | **谨慎助手**（默认） | 只读自动，写/删要确认 |
| L2 | **熟练助手** | 日常低风险写可自动 |
| L3 | **完全托管** | 高风险也可自动（删除等仍受 §3.9 底线约束） |

**数据密级**：

| 密级 | 举例 | 默认 |
|---|---|---|
| D0 公开 | 天气、时间、系统音量 | 所有等级可读 |
| D1 个人工作区 | 指定目录文档、待办、普通剪贴板 | L1+（谨慎助手+） |
| D2 私密 | 记忆库、备忘正文、账号类截图、含隐私字段文件 | L2+（熟练助手+），读取常需确认 |
| D3 核心机密 | 密钥/助记词/支付信息等凭据形态 | **永不进模型上下文**（规则拦截） |

**通行证读侧语义**：

| 通行证 | 动手（已有） | 看数据（新增） |
|---|---|---|
| L0 静默观察 | 一切需确认 | 仅 D0 |
| L1 谨慎助手（默认） | 只读自动，写确认 | D0–D1；D2 确认；D3 拦截 |
| L2 熟练助手 | 更多自动 | D0–D2；D3 拦截 |
| L3 完全托管 | 广泛自动（见 §3.9 删除底线） | D0–D2；**D3 仍拦截**（无全开档） |

**交叉防重复 / 防漏洞（用户强调，工程约束）**：

1. **单一事实源**：工具权限与数据密级的判定只允许存在一份策略定义（与既有 `tool_schema` / policy / 主进程终审同一套元数据体系）；禁止 Python 预检与主进程各写一份互不一致的密级表。
2. **只过一道「读」闸门**：数据进入 prompt 前统一经「密级过滤器」；工具执行仍走原双闸门——两者在架构上分层调用，禁止旁路（任何读文件/读剪贴板/读屏幕工具的结果必须先过滤再给模型）。
3. **D3 用规则过滤**，不靠模型自律；命中打码并在 UI 告知「含机密已遮蔽」。
4. **用户可加标、不可放行 D3**；设置 UI 展示当前通行证及其数据可见范围，避免「文档有、界面无」的空权限。
5. 落地时与调查报告既有安全项（信任等级无 UI、成功路径审计、浏览器白名单未执行）合并验收，避免另起炉灶再漏一层。

## 3. 议题三：本地 AI 轻量化架构 —— 三级任务路由 ✅ 已决

**拍板日期**：2026-09-11

### 3.1 决议摘要

| # | 决议 |
|---|---|
| D12 | 新增 **Router** 于 `/chat/stream`（及 `/chat`）入口；**Hermes 只服务生成式路径**（②③），规则命中不调用 Hermes/LLM |
| D13 | ②→③ 升级：**可观测规则信号为主、模型自评为辅** |
| D14 | 云端提示：**每类首次 + 岛内「本次上云」标记 + 一键仅本地熔断**；默认关闭 |
| D15 | 「复杂任务特征表」：内置默认清单 + 用户可增删（一期可与失败升级并行，表可为空启动） |
| D16 | 一期只上**硬规则层 + 失败升级**；轻分类器**二期**（AI Pack 可选、阈值回落、非单点依赖） |
| D17 | 用户规则：一期 `rules.json` + 最小开关 UI；二期完整规则管理器；规则不得越过通行证/密级 |
| D18 | **路由日志**每句必写（`route_log.jsonl`），与双闸门审计共用 `request_id` |
| D19 | **可逆执行铁律**：删除走回收站、移动/整理留 manifest 可撤回；规则层与 Hermes 层共用同一套可逆工具语义，禁止旁路 |

### 3.2 架构（D12）

```
用户文本
   ↓
Router（agent/router/，新增）
  ├─① 硬规则命中 → 工具执行器（同现有链路+双闸门）→ 模板回复/TTS → 路由日志 → 结束
  ├─① 未命中 → Hermes 本地内核（记忆注入 + _run_agent_loop）
  └─③ 失败/超限/特征/用户显式 → 云端适配器（默认关）
         仍用同一工具协议、双闸门、密级过滤；可复用记忆注入
```

**分工**：经过的是 Router；Hermes 是生成式阶段大脑，不是全量入口。云端不绕开协议，只换推理后端。

**与密级衔接（D9 延伸）**：路由只决定「在哪算」；数据能否进入上下文仍由密级过滤器把关；云端外传前再过滤，D3 永不外传。

### 3.3 语义划分原则（D16）

| 层 | 条件 | 动作 |
|---|---|---|
| 硬规则 | 闭集、可解析槽位、无需生成与多步规划、高频 | 模板 → 白名单工具 |
| 轻分类器（二期） | 规则变体召回；输出「是否某规则变体 + 置信度」 | 高置信 → 该规则；低置信/失败 → 落② |
| 本地 Hermes | 开放词汇、需规划与工具组合 | 本地闭环 |
| 云端 | 本地失败/超限/特征表/用户点名；且云端开关开 | 提示 → 确认/策略 → 执行 |

分类器保障：只增强规则召回、不新增能力面；未装 AI Pack 则无分类器；异常降级为「硬规则 + 本地 LLM」。误路由方向不得劣于「多跑一次本地 LLM」。

### 3.4 规则层与语音反馈（D12/D17 配套）

- 执行者：现有工具执行链（主进程终审），非 LLM
- 语音：唤醒词/热键 → STT → Router →（可选 TTS 模板回执）
- 每条规则默认必配 `reply_template`；**默认禁止无告知执行**（用户能感知做成了什么）
- `silent` 反馈形态是**用户显式选择**的覆盖，不是默认；选择 silent 后仍写路由/操作日志
- 示例：`「好的，音量已经调到 {level}% 了。」`
- 用户规则 JSON 示意：

```json
{
  "id": "volume.set",
  "patterns": ["音量\\s*(\\d+)", "声音调到\\s*(\\d+)"],
  "tool": "system.volume.set",
  "arg_map": { "level": "$1" },
  "reply_template": "好的，音量已经调到 {level}% 了。",
  "enabled": true,
  "priority": 100
}
```

### 3.8 执行反馈与人格回应（议题三补丁，已决）

**架构**：工具执行器与反馈层分离；**她解说结果，不代劳动手**。

| # | 决议 |
|---|---|
| E1 | **单一送达流**：情感角色模式下**只有一条**主回执（人格话术**吸收**事实，B 吸收 A），禁止「先陈述再吐槽」双播；纯工具/中立助手仅中性事实句 |
| E2 | 事实必须在场：人设可包装，必须能找回「做成了什么」 |
| E3 | 管线防堵：执行**零等待**反馈；回应簇本地选取（&lt;10ms）；即兴 LLM **异步 + 硬超时 + 节流 + 失败静默**；TTS 单槽可打断（确认 &gt; 结果 &gt; 闲聊）；高频操作合并回执 |
| E4 | 回应簇 = **情境 × 状态（mood/时段/频次/近期缓冲）× 人设包**；mood 接现有 PAD/circadian，失败回落中性；**mood 不影响授权与工具结果** |
| E5 | 反馈形态：`tts / island / popup / silent`，全局默认 + 单规则覆盖；**silent 默认无人格回应** |
| E6 | 「更自然的回应（即兴 LLM）」：仅**情感角色**模式下可选，**默认关**，显式开启才用 |

### 3.9 可逆执行（D19，唯一正文）

规则层与 Hermes 层共用同一套可逆工具语义，**不得为「快」绕开回收站/备份**。

| 操作 | 保障 |
|---|---|
| **删除** | **静默观察 / 谨慎助手 / 熟练助手**一律每次确认；**仅完全托管档**可经「专项授权 + 免责确认」关闭删除确认；**仍强制回收站**（`trashItem`）；禁止物理删；D3 永不自动 |
| 移动/整理 | 确认 + undo manifest；批量逐批确认 |
| 覆盖/同名 | 默认拒绝覆盖，改新名 |
| 审计 | 成功路径也记；`request_id` 串联路由日志 |
| 撤销 | 整理类可撤最近 N 次；设置页「操作记录」人读视图 |

### 3.10 通行证（用户可见权限模型）

**命名拆分（纠正历史混用）**：

| 系统 | 名称 | 管什么 |
|---|---|---|
| 角色模式 | **纯工具 / 中立助手 / 情感角色**（三分法，互斥单选） | AI 开不开、有没有人格 |
| **通行证（权限）** | 静默观察 / 谨慎助手 / 熟练助手 / 完全托管（= L0–L3） | 能看什么、能动什么 |

> **命名注意**：角色里的「中立助手」与权限里的「谨慎助手/熟练助手」字面都有「助手」，UI 文案必须用完整短语（如「角色：中立助手」「权限：谨慎助手」）或加图标区分，避免用户混淆。

**默认档**：谨慎助手。每档设置页展示：能做什么、能看哪级数据、确认策略、风险说明（权限说明卡）。

**授权形态（用户要求：可单次授予，非仅长期全局）**：

| 形态 | 生命周期 |
|---|---|
| 全局通行证 | 设置默认策略 |
| **仅此一次** | 该次操作后失效 |
| **本次会话** | 软件退出收回 |
| 工具级长期 | 设置页覆盖；**只能收紧**，不能突破底线（删除非完全托管必须问；D3 永拦） |

**完全托管**：全局提权 + 危险子开关（如免确认删除）需**专项二次确认 + 责任自负文案** + 完整审计；不是日常默认路径。

**权限说明卡**（每能力固定结构）：她会做什么 / 通常需要什么授权 / 接触哪些密级数据 / 风险 / 保护措施 / 可否覆盖。

**确认弹窗 UI（后续优化，先锁原则）**：标题+说明+风险徽章+按钮组；中危橙、高危红；**默认焦点不落危险钮**；低危可选「会话内不再询问」。

### 3.11 记忆沉淀（偏好与习惯）

## 4. 议题四：角色身份 = 可选开关 ✅ 核心已决

### 4.1 决议摘要

| D21 | **出厂默认：中立助手**（AI 开、无人格）；权限=谨慎助手；主动=关；云端=关 |
| D22 | 「AI 总开关」并入三分法：**纯工具 = 关 AI**，不再另设重复开关 |
| D23 | 情感角色模式下反馈走 §3.8 人格回应；能力与情绪正交不变 |

| D26 | 头像策略本轮不处理；建议见 §4.3，后续单独拍板 |

### 4.2 角色三分法定义

| 模式 | AI | 她怎么说 | 内容 |
|---|---|---|---|
| **纯工具** | **关** | 不说话 | 仅灵动岛工具箱；侧车/模型不启动（铁律一）；无对话入口或入口引导开启 AI |
| **中立助手**（出厂） | **开** | 中性、无性格、无情绪 | 规则直达 + 本地 AI + 事实回执；无牢骚/关心/主动 |
| **情感角色** | **开** | 有汐月人格 | 在中立助手之上：回应簇、mood、可选主动关心、可选即兴润色 |

**③ 内部子开关**（实现细节，不是第四种主模式）：表情差分、主动关心、更自然的回应（即兴 LLM）等，各自默认关或按前文决议。

### 4.3 头像建议（暂缓执行，供后续参考）

倾向：中立助手与情感角色下均使用汐月视觉品牌（识别统一）；纯工具可选「极简图标皮肤」。不阻塞本期。

## 5. 综合定位收敛稿（在 U1–U4 成立前提下）

> **汐月**是 Windows 顶栏的**本地 AI 工具箱**（独立开源品牌，受 eIsland 启发）。  
> **体**：灵动岛形态的系统工具与信息中枢。  
> **翼**：隐私优先的 AI——**Router 规则直达 / Hermes 本地推理 / 确认后可上云**；轻量可关，关了仍是完整工具箱；密级×通行证管「看与动」；可逆执行可恢复。  
> **魂（可选层）**：角色汐月——三分法（纯工具 / 中立助手 / 情感角色）；出厂中立助手；情感角色可有情绪与主动，但永不改写工具授权与密级底线。

一句话版：

> **「本地 AI 灵动岛：看一眼就知道，说一句就办好；模型不离机，角色随你开。」**
